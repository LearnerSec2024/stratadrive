# Local Supabase Compose configuration

This is a local development derivative of the official `supabase/supabase` distribution at `self-hosted/v0.8.3`, immutable commit `bc27d2661edd09a5d0b8d76ce33da6d4071a756e`. Exact upstream artifacts and hashes are in `provenance.json`; upstream Apache 2.0 licensing is retained in `upstream/LICENSE`.

The local `.gitattributes` preserves upstream bytes across Windows checkouts so artifact hashes remain valid and the gateway shell script retains its original line endings.

Use the orchestrator's guarded lifecycle commands documented in `docs/local-supabase.md`. Do not combine `compose.local.yaml` with the upstream reference Compose file: ordinary merging can retain wildcard published ports. The upstream files are references/bootstrap inputs, not an alternate startup entry point.

The standalone derivative starts only `db`, `rest`, `meta`, `studio` and `api-gw`. The upstream dependency closure needs no Auth, Storage, Realtime, Edge Functions, image proxy, analytics or pooler services. Their Studio navigation may still be visible but those features are unavailable. This does not implement customer authentication or any application API.

Local differences from upstream:

- Explicit loopback mappings: API `54321`, PostgreSQL `54322`, Studio `54323`. All remaining service ports stay inside the dedicated Compose network.
- Unique Compose project `stratadrive-local`; default project-scoped container/network/volume names; no upstream fixed global container names.
- PostgreSQL 17 image, exactly matching the pinned upstream PostgreSQL 17 configuration. Named `db-data` and `db-config` volumes retain development state; `snippets` holds only local Studio SQL snippets. The current physical data volume is `stratadrive-local_db-data-bootstrap-v2`; the first partially initialized `stratadrive-local_db-data` volume is retained, not deleted or reused.
- Credentials are required from the ignored development environment file generated by the guarded lifecycle helper. No workstation/cloud credentials, SMTP or AI integrations are inherited by this file.
- Read-only mounts preserve upstream webhook, roles/JWT bootstrap and Envoy templates. The webhook script creates `supabase_functions_admin`, which the next upstream roles script requires even without an Edge Functions service. It creates platform support objects only and makes no outgoing HTTP requests. `bootstrap/100-local-grants.sql` removes anonymous/authenticated public-schema access and implicit grants for new objects created by `postgres`, and revokes unused webhook-schema/function access from public roles. Later migrations must explicitly grant intended access. No application tables or sample customer records are created.
- Unused upstream analytics/realtime/pooler bootstrap mounts are omitted. Service restarts are disabled for controlled local review; lifecycle commands explicitly start/stop this project.
- Direct Studio on loopback `54323` is a development administrator interface. It bypasses the gateway's dashboard Basic Auth intentionally; do not expose or tunnel it. The gateway retains upstream API key checks and separate generated dashboard credentials.

Only setup/bootstrap artifacts are included. Never run broad Docker cleanup, delete volumes, use a remote Docker context or load production data. Follow the parent setup guide for shutdown and current runtime verification/owner acceptance status.
